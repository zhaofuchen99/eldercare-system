# 部署文档 · AI 智能养老社区管理系统

> 适用版本：需求规格 v1.0.3 / 详细设计 v1.0.8
> 技术栈：Spring Boot 4.1（Java 25）/ Vue3（Vant4 + Element Plus）/ MySQL 9.7 / Redis 7
> 交付形式：Docker Compose 单机编排（后端 + 会员端 + 管理端 + MySQL + Redis）

---

## 1. 架构与访问地址

```
                   ┌──────────────────────┐
     会员手机/电脑 → │ member（Nginx :80）   │──┐
                   └──────────────────────┘  │ /api
                   ┌──────────────────────┐  │
     管理员电脑 →    │ admin（Nginx :8081）  │──┼→ backend（:8080，容器内网）
                   └──────────────────────┘  │
                                            └→ mysql（:3306，容器内网）
                                            └→ redis（:6379，容器内网）
```

| 入口     | 地址                      | 说明                        |
|--------|-------------------------|---------------------------|
| 会员端    | `http://服务器IP/`（默认 80）  | 手机浏览器直接访问，可"添加到主屏幕"       |
| 管理端    | `http://服务器IP:8081/`    | 管理员操作                     |
| 后端 API | 不直接对外，经 Nginx `/api` 代理 | 数据库/Redis 不对外开放（设计文档 8.5） |

---

## 2. 环境要求

- 一台 **Linux 服务器**（云主机，建议 ≥2C4G；含 Vue 前端编译与 JVM，内存建议 4G 起步）
- 已安装 **Docker** 与 **Docker Compose**（`docker -v`、`docker compose version` 可验证）
- 服务器安全组/防火墙：开放 **80**（会员端）与 **8081**（管理端）；**不要**开放 3306/6379/8080
- 单仓库（monorepo）结构，前后端在同一工程内：

```
eldercare-system/
├── src/                     # 后端（Spring Boot）
├── sql/                     # 建库建表脚本
├── docs/                    # 部署 / 接口文档
├── docker-compose.yml       # 一键编排
├── web-member/              # 会员端（Vue3 + Vant）
└── web-admin/               # 管理端（Vue3 + Element Plus）
```

## 3. 快速部署

### 3.1 准备项目与配置

```bash
# 0) 克隆单仓库（前后端已合并，无需分别 clone）
git clone https://github.com/zhaofuchen99/eldercare-system.git
cd eldercare-system

# 1) 复制环境变量模板并修改密钥（必做）
cp .env.example .env
vi .env   # 至少修改：MYSQL_ROOT_PASSWORD、JWT_SECRET、REPORT_DOWNLOAD_SECRET；需要 AI 则填 DEEPSEEK_API_KEY
```

`.env` 关键项见第 5 节。

### 3.2 构建并启动

```bash
# 首次会拉取基础镜像 + 下载 Maven/npm 依赖，耗时较长（10~30 分钟属正常）
docker compose up -d --build

# 查看状态（全部 healthy 且无重启为正常）
docker compose ps

# 查看后端日志（含【模拟短信】验证码、启动信息）
docker logs -f eldercare-backend
```

启动顺序由 `depends_on` 保证：MySQL/Redis 健康后后端才启动，后端就绪后前端代理生效。

### 3.3 访问验证

| 检查    | 方法                                                                     |
|-------|------------------------------------------------------------------------|
| 会员端   | 手机/电脑浏览器打开 `http://服务器IP/`                                             |
| 管理端   | 浏览器打开 `http://服务器IP:8081/`                                             |
| 后端连通  | 浏览器访问 `http://服务器IP/api/member/health` 应返回 `{"code":401,...}`（未登录，属正常） |
| 登录    | 管理端用 `13800000000 / Admin@123456`，会员端用 `13800138000 / Test@123456`     |
| AI 对话 | 会员端发起对话，需 `.env` 中已配置真实 `DEEPSEEK_API_KEY`，否则消息打 FAILED（降级）            |

## 4. 数据库说明

- **自动初始化**：MySQL 容器首次启动时自动执行 `sql/init.sql`（建库 eldercare + 24 张表 + 初始数据 + RBAC 种子）。
- **重建/重跑**：如需重置数据库，`docker compose down -v` 会连同数据卷一起删除（谨慎，仅开发环境使用）。
- **手动执行 SQL**（如补种子）：

```bash
docker exec -i eldercare-mysql mysql -uroot -p'你的密码' eldercare < 某脚本.sql
```

## 5. 环境变量表（.env）

| 变量                       | 必填 | 默认          | 说明                                     |
|--------------------------|----|-------------|----------------------------------------|
| `MYSQL_ROOT_PASSWORD`    | ✅  | 无           | MySQL root 密码，务必修改                     |
| `JWT_SECRET`             | ✅  | 无           | JWT 签名密钥（≥32 字符），泄露会导致 Token 可伪造       |
| `REPORT_DOWNLOAD_SECRET` | ✅  | 有开发默认值      | 报告下载签名密钥，生产务必修改                        |
| `DEEPSEEK_API_KEY`       | 否  | 占位          | 填真实 key 后 AI 对话/评分可用；留空则降级（消息打 FAILED） |
| `MYSQL_IMAGE`            | 否  | `mysql:9.7` | 拉取失败可改 `mysql:9` 或 `mysql:8.4`         |
| `MEMBER_PORT`            | 否  | `80`        | 会员端对外端口                                |
| `ADMIN_PORT`             | 否  | `8081`      | 管理端对外端口                                |

## 6. HTTPS 配置（生产强制要求，设计文档 8.5）

当前编排默认走 HTTP，适合课程演示。**正式上线必须启用 HTTPS**，两种方式任选：

**方式 A：云厂商负载均衡终止 SSL（推荐，免改配置）**
云服务器安全组放行后，在云控制台配置域名解析 + SSL 证书（或全站加速），由 LB 终止 HTTPS，回源到服务器 80/8081。

**方式 B：Nginx 直接配置证书**
在两个前端工程的 `nginx.conf` 增加：

```nginx
listen 443 ssl;
ssl_certificate     /etc/nginx/certs/your_domain.pem;      # 证书链
ssl_certificate_key /etc/nginx/certs/your_domain.key;      # 私钥
```

并在 `docker-compose.yml` 的 member/admin 服务挂载证书目录：

```yaml
volumes:
  - /etc/nginx/certs:/etc/nginx/certs:ro
```

证书可申请免费证书（Let's Encrypt / 云厂商），域名需完成备案（国内服务器）。

## 7. 数据持久化与备份

- **数据卷**：`mysql-data`、`redis-data`、`app-data`（体检报告上传目录）均挂在 Docker 卷上，容器重建不丢失。
- **MySQL 备份**（建议加入定时任务）：

```bash
# 全量备份
docker exec eldercare-mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction eldercare' > backup_$(date +%F).sql
```

- **Redis**：已开启 AOF（`--appendonly yes`）。
- 设计文档 6.9 要求启用 binlog + 定期全量/增量备份，生产环境请按需开启（MySQL 容器 `command` 追加 `--log-bin` 等）。

## 8. 短信说明

- 当前为**本地模拟**（`MockSmsServiceImpl`），验证码与通知只打印到后端日志：`docker logs eldercare-backend | grep 模拟短信`。
- 课程/演示交付：够用，验收文档注明"短信为本地模拟"即可。
- **真实上线**（会员需自助注册/找回密码）：需接入短信服务商，替换 `SmsService` 实现类（阿里云/腾讯云等，约 3~5 分/条），业务代码无需改动。

## 9. 常见问题

| 现象                                              | 原因与处理                                                                                       |
|-------------------------------------------------|---------------------------------------------------------------------------------------------|
| `docker compose up` 报 `MYSQL_ROOT_PASSWORD` 未设置 | 未执行 `cp .env.example .env` 或 .env 缺项                                                        |
| MySQL 容器一直重启                                    | 首次初始化 init.sql 报错。`docker logs eldercare-mysql` 查看；本地已跑过则 `docker compose down -v` 清卷重来     |
| 访问会员端页面空白 / API 502                             | 后端尚未就绪（首次构建慢）。等 `docker compose ps` 中 backend healthy；或 `docker logs eldercare-backend` 看报错 |
| AI 对话消息打 FAILED                                 | `.env` 未配真实 `DEEPSEEK_API_KEY`（占位 key 无法真实调用，属预期降级）                                         |
| 前端构建失败                                          | 多为 npm 依赖问题：删除工程的 `node_modules` 后 `docker compose build --no-cache member admin`           |
| `mysql:9.7` 镜像拉取失败                              | `.env` 中 `MYSQL_IMAGE` 改为 `mysql:9` 或 `mysql:8.4`（表结构兼容，需 MySQL 8+）                         |
| 端口 80/8081 被占用                                  | `.env` 中改 `MEMBER_PORT` / `ADMIN_PORT`                                                      |
| 手机访问不了                                          | 同一 WiFi 仅限局域网测试；公网需云服务器 + 安全组放行 80/8081                                                     |
| 对话卡住无打字机效果                                      | Nginx 需 `proxy_buffering off`（两个 nginx.conf 已内置）；确认访问的是 Nginx 而非直连后端                        |

## 10. 日常运维

